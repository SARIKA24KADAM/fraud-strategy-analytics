# Alignment to a fraud performance management role

| Role area | Project demonstration |
|---|---|
| Mine transaction data | DuckDB CSV-to-Parquet preparation and SQL analysis |
| Python and analytical tooling | Python, pandas, NumPy-compatible data work, DuckDB, scikit-learn |
| Product/channel strategies | Transaction type segmentation (a simulator proxy, not a true channel taxonomy) |
| Intraday monitoring | Hourly transaction and simulated-fraud summaries |
| Optimize existing rules | Baseline simulator flag compared with candidate model thresholds |
| Balance loss, customer experience, and operations | Fraud dollars captured alongside legitimate alerts and review-volume assumptions |
| Executive communication | Summary metrics and documented recommendation framework |
| Risk appetite and governance | Shadow-mode guardrails, leakage controls, limitations, and monitoring risks |

This project demonstrates methods, not professional tenure or production banking experience. PaySim cannot demonstrate effectiveness against real first- or third-party fraud.
